## Architecture and correctness decisions

- PostgreSQL remains authoritative for attendance, timesheets, payroll, payout state, idempotency evidence, audit and outbox records.
- Attendance projection is rebuildable from closed sessions plus immutable correction overlays; realtime remains a refetch signal.
- Money aggregation stays in PostgreSQL `bigint`/minor units and crosses the API boundary as exact strings where required.
- Provider payment creation uses one stable key per payout item. Ambiguous outcomes reconcile before any further payment attempt.
- Payroll corrections use supplemental delta sources and never mutate a finalized original run or statement.
