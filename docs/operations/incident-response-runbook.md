# Incident Response Runbook

1. Page the incident commander and record start time.
2. Classify severity and impact; preserve request IDs and redacted logs.
3. Contain: stop rollout, disable affected feature/provider, or isolate tenant scope.
4. Recover using backup/DR or rollback runbook; verify data integrity.
5. Communicate status at the cadence in the severity matrix.
6. Close only after monitoring is stable and a postmortem owner/date is assigned.
